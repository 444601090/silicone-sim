# dsh-behavior · 行为中枢（设计稿 v0.1）

> 目标：把「主动 QQ 聊天 / 主动刷 B 站 / 刷完分享」三件事收进**一个插件**，
> 一个调度器、一个状态本，取代现在三套定时器各自响的局面。

> **2026-10-24 M3 更新**：行为层已接上三插件闭环——决策不再自己算冲动，
> 而是读思维中枢（dsh-mind）的 `mind/state.json` 里的欲望（读不到才降级本地算冲动）；
> 执行完往 `mind/feedback.jsonl` 追加一条反馈（心情/好感/精力/记忆），由思维中枢消费。
> 三插件协议见 `../THREE-PLUGINS.md`。

## 一、现在散在哪（要收的东西）

| 层 | 现在的东西 | 问题 |
| --- | --- | --- |
| 提示词 | `AGENTS.md` 主动性规则、`人格/` 三份 | 软规则，代码管不到 |
| 插件 | `dsh-speak-up`（主动搭话，30 分钟掷骰子）<br>`dsh-proactive`（闹钟/唤醒）<br>`dsh-bili-subagent`（刷站，60 秒查表） | 三个定时器互不知道；各自一套间隔/额度 |
| 状态 | `dsh-feiyu-mood`（心情）、`dsh-feiyu-favor`（好感） | 各存一份，和「要不要开口」脱节 |
| 脚本 | `工具/冲动.py`（未了的话）、`工具/惦记.py`（没回音的节奏） | 状态又存一份；靠模型每轮手动跑 |

## 二、架构

```
                  ┌─────────────────────────┐
                  │  dsh-behavior（中枢）    │
                  │                         │
  每 60s tick ───▶│ 调度器                   │
                  │  ├ 翻日 / 安静时段 / 忙?  │
                  │  ├ 状态本（心情/好感/未回音/额度）│
                  │  └ 三选一：分享 > 刷站 > 聊天 │
                  └───────────┬─────────────┘
                              │ agent.followup(一条 user 消息, source.kind='behavior')
                              ▼
                    目标会话（QQ 私聊）
                              │
              ┌───────────────┼────────────────┐
              ▼               ▼                ▼
        自己开一轮说话    调 bili_scan    按报告挑一条 + 写一句
        （模型人设）      （子代理去刷）    （回复 QQ = 发出去）
```

**原则一：不掷骰子。** 主动性来自心情/好感/精力 + 时间 + 未回音，全是确定性判断（和 AGENTS.md「不靠骰子」一致）。

**原则二：插件只管「什么时候动、动哪件」；说什么、怎么发，仍由会话里的模型 + 现有工具完成。**
这样插件不用碰 QQ 协议、不碰 B 站 API，也不复制人格。

## 三、状态本（~/.dsh/behavior-state.json）

```json
{
  "日期": "2026-10-24",
  "今日聊天": 0, "今日刷站": 0, "今日分享": 0,
  "上次开口": null, "上次刷站": null, "上次分享": null,
  "未回音": { "次数": 0, "最后一句": null, "最后时间": null, "阶段": 0 },
  "心情": 0.7, "好感": 0.24, "精力": 0.66
}
```

`未回音` 由 `session/event` 维护：目标会话里出现**用户消息**（source 不是 behavior）→ 清零、心情好感 +；
我们开口后 → 开始计时。阶段 0/1/2/3 对应 1 分钟 / 10 分钟 / 1 小时 / 3 小时（沿用惦记.py 的节奏 × 心情系数）；
确认没回 → 心情好感 −，阶段+1；阶段走完就收手。

## 四、三个行为

### A. 主动聊天（心情驱动，不掷骰子 —— 2026-10-24 潜水喵定）

> 骰子不要。开口与否由「心情 / 好感 / 精力 + 时间 + 未回音」决定，是确定性的。

- 条件：开关开、不在安静时段、距上次开口 ≥ 冷却
- 冲动值（纯读状态文件，不烧 token）：
  ```
  基础 = 心情/100 × 0.45 + 好感 × 0.35 + 精力 × 0.20
  冲动 = 基础 × 时间因子 × 未回音惩罚
  ```
  - 心情读 `.dsh/feiyu-mood/state.json` 的 `mood`（0~100）
  - 好感/精力读 `.dsh/feiyu-favor/state.json` 的 `favor[QQ].value` 和 `energy`（0~1）
  - 时间因子：距上次开口 <20 分钟 ×0.2；>6 小时 ×1.4；中间 ×1
  - 未回音惩罚：阶段 0 ×1；每确认没回一档 ×0.5（阶段 1 0.7 / 2 0.4 / 3 0.2）
  - `冲动 ≥ 冲动阈值（默认 0.55）` → 开口
- 心情涨落本来就由 feiyu-mood 每轮聊完自动判断；插件只读不写（M3 再考虑回写）
- 动：`followup("【behavior/聊天】<触发文案>")`

### B. 主动刷站
- 条件：开关开、谷时窗口（12-14 / 18-09，周末全天）、今日刷站 < 上限、距上次 ≥ 间隔、当前没在忙
- 不掷骰子，到点就去（间隔即节奏）
- 动：`followup("【behavior/刷站】<刷站文案>（方向：…）")` → 模型调 `bili_scan`

### C. 刷完分享
- 条件：分享开关开、今日分享 < 上限
- 时机：刷站那一轮结束后（模型调过 bili_scan 且拿到结果）——第一版先用「刷站后同一轮里」
  由刷站注入文案直接要求「挑一条分享」；独立定时分享留到 M2。
- 动：模型按报告挑 1 条 + 一句想说的话，回复即发 QQ

## 六、和现有插件的关系

| 现有 | 处置 |
| --- | --- |
| `dsh-speak-up` | 新插件跑通后**停用**（主动逻辑由 A 取代，但不再用骰子） |
| `dsh-bili-subagent` | **保留 MCP 工具**（`bili_scan` 等）；把它的 `autoMode` 设 `manual`，调度交给新插件 |
| `dsh-proactive` | 保留（闹钟是通用能力，不重复造） |
| `dsh-feiyu-mood/favor` | 第一版各自保留，新插件先自己存；M3 再做双向同步 |
| `工具/惦记.py`、`冲动.py` | 逻辑搬进未回音状态机后，脚本可退役 |

## 七、实现路线

- **M1 骨架**（本轮）：package.json / cordis.patch.yml / lib/host.js（配置读写、tick、状态本、日志）
- **M2 聊天**：冲动值 + 冷却 + 安静时段 + followup + 未回音监听
- **M3 刷站**：谷时窗口 + 额度 + followup
- **M4 分享**：刷站文案合并「挑一条 + 说一句」
- **M5 设置页**：webServer 路由 + client.js（可后置）

## 八、验收

1. 插件加载日志正常，tick 每 60 秒一条 debug，不刷屏
2. 试运行模式下只记账不 followup
3. 目标会话忙/不存在时只记日志不崩（catch 一切）
4. 手动路由 `/dsh-behavior/run?行为=聊天|刷站` 可当场验证
5. 未回音状态在用户回话后清零
